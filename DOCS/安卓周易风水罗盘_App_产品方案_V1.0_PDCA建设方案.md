> 项目代号：**ShineFS**  
> 本地仓库：`F:\ClaudeWorkSpace\projects\ShineFS`  
> 文档定位：产品建设方案 + 技术实施约束 + Agent 自主推进规范  
> 建设方式：**PDCA（Plan-Do-Check-Act）闭环迭代**  
> 目标平台：Android  
> 核心定位：**以《周易》卦象体系为根本，以手机空间传感器为输入，以八卦、二十四山、六十四卦及明确的起卦规则为演算核心，构建具备动态罗盘、定盘、起卦、解卦、宅居测局和卦例留存能力的传统术数工具。**

## 0. Agent 总执行指令

本项目由 Agent 自主推进建设。Agent 必须遵循以下总原则：

1. **先理解现有代码，再修改。**
   - 每轮开始必须扫描项目结构、Gradle 配置、现有页面、依赖、资源文件、测试目录和版本控制状态。
   - 不允许假设项目为空，也不允许在不了解现状的情况下大规模重构。
   - 优先复用既有架构、组件和设计体系。

2. **必须采用 PDCA 闭环。**
   - 任何一个功能都不得直接“写完即结束”。
   - 每项工作必须经历 `Plan → Do → Check → Act`。
   - Check 不通过时，必须进入 Act 修正，再重新 Check，直到达到验收标准。

3. **算法与 AI 必须解耦。**
   - 方位、八卦、二十四山、本卦、动爻、变卦等必须由确定性规则引擎计算。
   - AI 只负责白话解释、内容组织和辅助说明。
   - AI 不得决定卦象，不得自行创造卦辞、爻辞、五行、方位或术数规则。

4. **传统术数体系不得混用。**
   - V1.0 只使用本方案明确定义的体系。
   - 任何新增流派、飞星、奇门、六爻纳甲、八字、紫微等内容，未经产品规则确认不得自行加入。
   - 如发现不同古籍、流派存在冲突，应记录为“待决策项”，不能擅自取一种作为唯一正确答案。

5. **经典文本必须可溯源。**
   - 六十四卦、卦辞、爻辞等原典内容必须来自经人工核定的数据文件。
   - 不允许由大模型临时生成经典原文。
   - 规则数据必须版本化。

6. **UI 不能做成普通科技指南针。**
   - 整体视觉必须体现传统罗盘、天池、八卦、二十四山、朱砂、玄黑、古铜金、古籍纹理等数术特征。
   - 动效需有“定盘、起卦、爻变”的仪式感，但不能过度炫技。

7. **任何一轮改造不得以“编译成功”作为唯一完成条件。**
   必须同时完成：
   - 编译检查
   - 单元测试
   - UI/交互检查
   - 关键逻辑验算
   - 异常场景检查
   - 代码质量检查
   - 文档同步

8. **每轮输出必须可追踪。**
   建议在仓库中维护：
   - `docs/PRODUCT_V1.md`
   - `docs/ARCHITECTURE.md`
   - `docs/YIJING_RULES.md`
   - `docs/PDCA_LOG.md`
   - `docs/TEST_MATRIX.md`
   - `CHANGELOG.md`

# 1. 产品目标

## 1.1 产品愿景

将 Android 手机本身变成一块具备空间感知能力的“电子周易罗盘”。

用户在住宅、办公室、商铺、工位、卧室、大门等实际空间中，通过手机电子罗盘测向，获得：

- 当前方位角
- 八方方位
- 后天八卦
- 二十四山
- 五行属性
- 坐向关系
- 基于规则的本卦
- 动爻
- 变卦
- 原典内容
- 风水/空间解释
- AI 白话解读
- 历史卦例

核心体验必须形成：

`举起手机 → 罗盘随方向动态旋转 → 稳定定盘 → 锁定山向 → 起卦 → 六爻生成 → 动爻变化 → 输出结构化解释`

# 3. 方位与罗盘基础规则

## 3.1 八卦方位

采用后天八卦方位：

| 方位 | 八卦 | 卦符 | 五行 |
|---|---|---|---|
| 北 | 坎 | ☵ | 水 |
| 东北 | 艮 | ☶ | 土 |
| 东 | 震 | ☳ | 木 |
| 东南 | 巽 | ☴ | 木 |
| 南 | 离 | ☲ | 火 |
| 西南 | 坤 | ☷ | 土 |
| 西 | 兑 | ☱ | 金 |
| 西北 | 乾 | ☰ | 金 |

> 注意：实现时必须明确角度边界策略，并通过单元测试验证临界值。

## 3.2 二十四山

二十四山按 360° 等分，每山 15°：

`壬、子、癸、丑、艮、寅、甲、卯、乙、辰、巽、巳、丙、午、丁、未、坤、申、庚、酉、辛、戌、乾、亥`

推荐中心角：

| 山 | 中心角 |
|---|---:|
| 子 | 0° |
| 癸 | 15° |
| 丑 | 30° |
| 艮 | 45° |
| 寅 | 60° |
| 甲 | 75° |
| 卯 | 90° |
| 乙 | 105° |
| 辰 | 120° |
| 巽 | 135° |
| 巳 | 150° |
| 丙 | 165° |
| 午 | 180° |
| 丁 | 195° |
| 未 | 210° |
| 坤 | 225° |
| 申 | 240° |
| 庚 | 255° |
| 酉 | 270° |
| 辛 | 285° |
| 戌 | 300° |
| 乾 | 315° |
| 亥 | 330° |
| 壬 | 345° |

实现建议：

```text
index = floor(((azimuth + 7.5) % 360) / 15)
```

具体数组顺序必须经过人工复核，并建立 0°、7.49°、7.5°、352.5°、359.99° 等边界测试。

## 3.3 坐向

用户手机所朝方向为“向”，其相反方向为“坐”。

```text
facing = azimuth
sitting = (azimuth + 180) % 360
```

定盘结果必须同时显示：

- 向首角度
- 向山
- 坐山
- 所属八卦
- 五行
- 稳定度
- 磁场干扰状态

# 4. 起卦规则设计

## 4.1 核心要求

起卦规则必须：

- 可重复
- 可测试
- 可解释
- 可记录
- 不依赖 AI 随机生成

## 4.2 V1.0 推荐模式

### 模式 A：方位起卦

用途：空间测风水。

建议规则：

- 上卦：取“向”所属后天八卦
- 下卦：取定盘时刻按既定时间规则换算
- 动爻：由时间数值求余

该规则必须在 `YIJING_RULES.md` 中以公式形式固化。

### 模式 B：时间起卦

用途：不依赖空间测向的一般起卦。

必须使用明确年月日时换算算法，不允许 AI 自行理解。

### 模式 C：手动数字起卦

用户输入 2～3 个数字：

- 数字一 → 上卦
- 数字二 → 下卦
- 数字三 → 动爻

所有求余规则必须统一。

## 4.3 本卦与变卦

六十四卦必须采用明确的上下卦编码映射。

动爻变化规则：

- 阴爻变阳爻
- 阳爻变阴爻
- 只变指定动爻
- 由变化后的六爻重新映射变卦

必须为全部 64 卦及 6 个动爻建立自动化验证。

# 6. Android 技术架构建议

## 6.1 推荐技术栈

优先采用：

- Kotlin
- Jetpack Compose
- Material 3 作为底层交互能力，但视觉需高度自定义
- MVVM / MVI 二选一，优先沿用现有仓库架构
- Coroutines + Flow
- Hilt（若已有依赖则复用）
- Room：卦例与规则版本存储
- DataStore：用户设置
- Android SensorManager
- Rotation Vector Sensor 优先
- Magnetometer + Accelerometer 作为兼容回退方案
- Canvas / Compose DrawScope 绘制动态罗盘

禁止为了实现视觉效果而引入过重的 3D/游戏引擎。

## 6.2 传感器优先级

优先级：

1. `TYPE_ROTATION_VECTOR`
2. `TYPE_GAME_ROTATION_VECTOR` 仅作辅助，不作为磁北基准
3. `TYPE_ACCELEROMETER + TYPE_MAGNETIC_FIELD`

必须检测：

- 当前设备是否存在磁力计
- 传感器精度状态
- 磁场明显异常
- 是否需要“8 字校准”

## 6.3 罗盘平滑

禁止直接把原始 azimuth 映射到 UI。

必须增加：

- 环形角度平滑
- 0°/360°跨界处理
- 低通滤波或指数平滑
- 异常突跳抑制
- 定盘稳定阈值

建议设计：

```text
rawSensor
  ↓
orientationCalculation
  ↓
angleNormalization
  ↓
circularSmoothing
  ↓
stabilityDetector
  ↓
CompassState
  ↓
UI
```

稳定度至少分：

- 不稳定
- 一般
- 良好
- 已定盘

# 8. 动态罗盘设计

## 8.1 罗盘层级

建议从外到内：

1. 360°角度刻度
2. 八方方位
3. 二十四山
4. 十二地支辅助层
5. 八卦层
6. 五行层
7. 天池
8. 中央磁针/定向指示
9. 当前山向高亮

## 8.2 旋转逻辑

推荐交互：

- 手机旋转时：罗盘盘面相对方向动态旋转
- 顶部固定“当前向首指针”
- 用户容易理解“我现在面对哪个山向”
- 支持切换“盘转 / 针转”显示模式，但 V1 默认只保留一种最直观方案

## 8.3 动效

### 动态 1：自然旋盘
- 30～60 FPS
- 平滑
- 跨越 359°→0°时不得反向转一整圈

### 动态 2：磁针微摆
- 未稳定时轻微摆动
- 稳定后逐步衰减

### 动态 3：定盘
稳定达到阈值后：

1. 当前二十四山高亮
2. 当前卦位描边
3. 天池轻微扩散
4. 朱砂“定”印短暂浮现
5. 触觉反馈
6. 锁定测量值

### 动态 4：起卦
六爻必须从下向上依次生成。

流程：

```text
初爻 → 二爻 → 三爻 → 四爻 → 五爻 → 上爻
```

动爻生成后：
- 朱砂色标记
- 发生阴阳翻转动画
- 本卦过渡到变卦

### 动态 5：五行关系
仅在解释页面做微弱流动提示，禁止喧宾夺主。

## 10.2 AI 权限

AI 可以：

- 将经典内容转换为现代白话
- 解释象义之间的关系
- 根据空间场景组织建议
- 标明不确定性
- 输出通俗版本

AI 不可以：

- 修改原始测量值
- 修改本卦
- 修改动爻
- 修改变卦
- 自创经典文本
- 将某个流派说成“唯一正确”
- 做医疗、投资、法律等高风险决定替代

# 11. 异常与真实设备问题

必须处理：

## 11.1 手机没有磁力计
显示：

> 当前设备不具备完整电子罗盘传感能力，本功能仅可使用有限模式。

不得伪造方向。

## 11.2 磁场干扰
当磁场值或方向波动异常时：

- 提示远离金属桌面、音箱、磁吸手机壳、汽车等
- 暂停定盘
- 显示“磁场环境异常”

## 11.3 未校准
提供 8 字校准引导动画。

## 11.4 手机姿态问题
如果倾斜角过大：
- 提示尽量水平持机
- 或实现 tilt compensation

## 13.1 每轮 PDCA 模板

### P — Plan
